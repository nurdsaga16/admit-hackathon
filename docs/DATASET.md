# Проверка исходного датасета

Проверено 30.09.2026. Источник: [Kaggle — Sign Language Recognition](https://www.kaggle.com/datasets/metehanzdeniz/sign-language-recognition/data).

## Доступ и сохранность

Публичные API `https://www.kaggle.com/api/v1/datasets/list/metehanzdeniz/sign-language-recognition` и `https://www.kaggle.com/api/v1/datasets/download/metehanzdeniz/sign-language-recognition` ответили HTTP 200 без авторизации. Архив ZIP: 168 433 034 байта; единственный файл — `sign-language-recognition.sqlite`, 396 537 856 байт. Если доступ изменится и потребуется вход, нужно скачать файл вручную через Kaggle; обход авторизации не предусмотрен.

База открыта через SQLite URI `mode=ro` и `PRAGMA query_only=ON`. SHA-256 до и после чтения: `8d27dcc68f99ce004c0a49cd3464ef8e10c0f616acf39fc426370e5022ce5f4e`. Архив и база находятся в игнорируемой папке `data-local/`. Производные JSON в `web/public/dataset-examples/` также исключены из Git. Веса модели не изменены.

## Фактическая структура

| Таблица | Строк | Поля |
|---|---:|---|
| `video` | 1 102 | `id INTEGER`, `path TEXT`, `label TEXT`, `duration REAL`, `created_at TEXT` |
| `frame_landmark` | 7 639 533 | `id INTEGER`, `video_id INTEGER`, `frame_index INTEGER`, `hand INTEGER`, `landmark_id INTEGER`, `x REAL`, `y REAL`, `z REAL`, `type TEXT` |
| `video_feature` | 411 498 | `id INTEGER`, `video_id INTEGER`, `feature_name TEXT`, `value REAL`, `start_frame INTEGER`, `end_frame INTEGER` |

Также есть служебная `sqlite_sequence`. Полные схемы и количество записей сохраняются экспортёром в локальный `audit.json`.

`video.path` содержит локальные пути Linux к `.webm` (имена вида `20250430_103636.webm`), а не доступные ссылки. HTTP-путей: **0**. В архиве видеороликов нет; соответствующих локальных файлов в проекте не найдено. Поэтому ссылки на оригиналы и вид исполнителя восстановить не удалось.

`frame_landmark` содержит все точки кисти **0–20**, тела **0–22**. Это не только кончики пальцев и не только агрегированные признаки. Точки нижней части тела, подробная мимика, visibility, handedness, FPS, размер изображения и флаг зеркальности не сохранены. `hand` встречается со значениями **−1, 0, 1, 2** даже для `type=hand`; считать их анатомической стороной нельзя.

## Повторные наблюдения и зеркальность

В одном `video_id/frame_index` встречается несколько полных наборов одних и тех же точек. В выбранных записях бывает до четырёх блоков на кадр, и число блоков меняется.

Сохранённый `app/tasks.py` сначала обрабатывает исходный кадр, затем `cv2.flip(frame, 1)`. Для второго прохода записывает `x = 1 − x` и меняет индекс кисти; оба прохода получают одинаковый `frame_index` без признака происхождения. Повторные обработки также нельзя надёжно отличить. Соответствие конкретного блока конкретному проходу не доказано: версия обработчика при записи могла отличаться, а при отсутствии детекции порядок наблюдений меняется.

Экспортёр читает строки по `frame_index,id` и разделяет их по окончанию полного набора `pose 0…22`. Полные кисти сохраняются в том же блоке по порядку записи. Это **предположение о группировке**, а не восстановленные оригинал и зеркало. Блоки не усредняются и не смешиваются. Повтор ключа внутри блока, неполная кисть или неполный pose дают пустой блок. В 33 выбранных записях такие невалидные блоки не обнаружены; отсутствующий порядковый блок в отдельных кадрах всё равно показывается пустым. Порядковый номер не гарантирует единую идентичность прохода на всей записи.

Страница отображает нормированные XY в квадрате, без восстановления пропорций исходного кадра. По умолчанию X сохранён как в базе; переключатель только отражает отображение `X → 1 − X`. Y направлен вниз. Z сохранён в JSON, но не используется в двумерном рисунке. Проигрываются только сохранённые кадры, без интерполяции. Устанавливаемые 15 кадров/с — условная скорость просмотра, не подтверждённый FPS оригинала.

## Подготовка и просмотр

Из корня проекта, PowerShell (скачивание около 168 МБ, база около 397 МБ):

```powershell
New-Item -ItemType Directory -Force data-local
Invoke-WebRequest 'https://www.kaggle.com/api/v1/datasets/download/metehanzdeniz/sign-language-recognition' -OutFile data-local/dataset.zip
Expand-Archive data-local/dataset.zip -DestinationPath data-local
python scripts/export_dataset_examples.py data-local/sign-language-recognition.sqlite
npm --prefix web run build
npm --prefix server start
```

Открой **http://127.0.0.1:3001/?mode=examples** или ссылку «Примеры движений из датасета» на главной. В dev-режиме адрес **http://127.0.0.1:5173/?mode=examples**. Выбери слово, запись и блок; используй паузу, ползунок кадров и отражение. Для проверки модели отдельно открой `?mode=local`. Экспортёр поддерживает `--per-class N`; по умолчанию 3. Полученные примеры не подаются в рабочее распознавание и не меняют веса.

Без подготовленных локальных JSON страница показывает инструкцию подготовки, без фиктивных движений. Для публикации сборки с данными необходимо отдельно проверить право на распространение датасета; MIT-лицензия кода не устанавливает лицензию данных. Публикация не выполнялась.

## Практические ограничения

По этим координатам можно посмотреть пример траектории и конфигурации пальцев, связанный с меткой. Нельзя подтвердить правильность исполнения, жестовый язык, анатомическую сторону, ориентацию исходной камеры и точный темп. Для полноценной инструкции нужны исходные видео, сведения об ориентации и проверка носителем/специалистом. Словарь не расширен; Hello / How are you? / I’m fine не обучены.
