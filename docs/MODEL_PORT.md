# Перенос исходной модели

## Проверенные артефакты

Используется заимствованная модель из исходной ревизии `eb069bd0740ee916eb22e11069f8602800d6af2c`. Исходные файлы и MIT LICENSE сохранены.
Хеши четырёх исходных артефактов записаны в `web/public/model/metadata.json`.

- Keras: вход `(batch, 5, 18)`, LSTM(128, return_sequences), Dropout, BatchNormalization, LSTM(64), Dropout, BatchNormalization, Dense(64, relu), Dropout, Dense(11, softmax).
- Оба LSTM используют tanh и sigmoid, без stateful и обратного прохода; начальные состояния нулевые для каждого предсказания. BatchNormalization использует сохранённые moving mean/variance, epsilon 0.001. Dropout выключен при inference.
- Реальный LabelEncoder: `afternoon, age, boy, country, day, monday, name, night, people, person, time`. Новые выражения не добавлялись.
- StandardScaler: 18 mean/scale, нормализация `(x - mean) / scale`, затем float32. Пропавшая рука даёт нули **до** нормализации.
- Порядок признаков взят из `feature_order.json`: joints, left_tips, right_tips; в каждой группе x_mean, x_std, y_mean, y_std, z_mean, z_std.
- Используются кончики пальцев 4/8/12/16/20 и плечи/локти/запястья 11–16. Координаты нормализованные MediaPipe, z сохраняется без дополнительного масштабирования.

## Совместимость и известные расхождения upstream

| Аспект | Обучение/подготовка | Исходный realtime и выбранный перенос |
|---|---|---|
| std | pandas std, ddof=1 | numpy std, ddof=0; сохранено |
| Руки | Индекс обнаружения; имена left/right не обозначают анатомическую сторону | Индекс обнаружения сохранён; по handedness не сортируем |
| Зеркальность | `process_video_landmarks(mirror=True)` добавляет исходные и зеркальные точки под теми же video/frame; для зеркальных рук меняет индекс и x обратно | Вход незеркальный; зеркало только CSS у видео и наложения |
| Окна | 7 индексов исходных кадров, хотя видео прореживается примерно до 15 FPS | 7 реально обработанных кадров; 5 окон, сдвиг одно окно |
| Частота | round(source_fps/15); индексы не перенумеровываются | standalone использует floor fps/15; Flask обрабатывает каждый полученный кадр. Браузер ограничен 15 обработками/с, пропускает повторные кадры |
| Пропуски | Отсутствующая рука: нули. Нет pose: NaN; сохранение пропускает NaN | Среднее/std только по присутствующим точкам, пустая группа: нули |
| Разделение данных | Перекрывающиеся последовательности одного видео случайно распределены; scaler обучен до split | Не переобучаем; заявленные upstream метрики не считаем независимой оценкой |

По имеющимся артефактам нельзя восстановить FPS каждого обучающего видео, фактический флаг mirror, точное происхождение каждой последовательности и жестовый язык. Английские подписи не доказывают ASL. Эти расхождения могут ухудшать распознавание; исправление обработки обучения требует отдельных данных и переобучения. Веса не менялись.

Браузерный MediaPipe Tasks отличается от Python Solutions 0.10.21. Схема координат совпадает, но численное совпадение детекторов и порядок двух рук на одинаковом видео **не доказаны**. Тест ниже начинается с готовых landmarks. Он не проверяет одинаковость пиксели → landmarks и качество перевода.

## Реализация экспорта

Выбран ONNX Runtime Web, WebAssembly CPU, один поток. Официальная [документация runtime](https://onnxruntime.ai/docs/get-started/with-javascript/web.html) описывает браузерный WASM backend; [Keras LSTM](https://keras.io/api/layers/recurrent_layers/lstm/) — исходную семантику. MediaPipe подключён по [официальному Web API](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js).

`scripts/export_model.py` загружает настоящую Keras-модель и разворачивает пять шагов каждого LSTM в ONNX opset 13, IR 8. Порядок gates Keras — i/f/c/o. Использованы MatMul, Gather, Add/Sub/Mul/Div, Sigmoid/Tanh, Relu, Softmax, Identity. Веса не квантуются. Размер ONNX: 562 979 байт; вход фиксирован `[1,5,18]`.

Это специализированный экспортёр проверенной архитектуры, а не универсальный конвертер Keras. Он отклоняет неподдерживаемую структуру. TensorFlow.js также рассмотрен по [официальной документации конвертации](https://www.tensorflow.org/js/guide/conversion); выбран явный ONNX-граф для небольшой фиксированной последовательности и проверяемого соответствия.

При первом браузерном тесте Vite неверно обрабатывал импорт runtime `.mjs` из public. Исправлено явным импортом `?url`; WASM задан отдельным локальным URL. Серверный inference и моки в приложение не добавлялись.

## Поведение прототипа

- Кадр замораживается в canvas перед обоими детекторами. Одновременно выполняется только одна обработка, следующая начинается после завершения предыдущей.
- Одна рука допустима. Если рук нет, необходимые точки тела не видны, есть нечисловые координаты или рука у края — сбрасываются все окна и черновик. Пропуски в математическом переносе проверяются отдельно синтетическими данными.
- Пауза кадров более 350 мс сбрасывает последовательность; приложение останавливается при скрытии вкладки. Медленное устройство может не накопить последовательность — нужна отдельная проверка производительности.
- По умолчанию: оценка ≥0.8, отрыв от второго класса ≥0.2, три подряд новых окна с одним кандидатом. Параметры настраиваются; это экспериментальные значения.
- Только устойчивый кандидат доступен для ручного подтверждения. История хранится в памяти вкладки. Неизвестные движения могут получать высокую softmax-оценку: у модели нет reject/neutral класса.
- Удерживаемое подтверждённое слово блокируется до другого подтверждённого слова либо отсутствия рук ≥800 мс. Краткая потеря отслеживания, низкая уверенность и очистка истории не снимают блокировку повтора.
- Остановка выключает все tracks, ждёт текущую обработку и освобождает MediaPipe и ONNX. Повторный запуск загружает их снова.

На этапе переноса модели команды отсутствовали. Теперь условные команды реализованы отдельно по геометрии полной кисти (см. README), без изменения признаков ONNX. Полный сценарий хакатона этим этапом не закрыт.

## Воспроизводимая проверка

Экспортёр извлекает чистые методы `extract_window_features` из двух исходных Python-файлов через AST, исполняет их без Flask/OpenCV и проверяет их равенство. Для 16 синтетических последовательностей landmarks (включая отсутствие обеих/одной руки и частичные пропуски) сохраняет признаки, StandardScaler и выход Keras. Ещё 16 входов проверяют модель на нормализованных тензорах разных масштабов. Seed: 20260930.

`web/tests/fixtures/parity.json` маркирован `synthetic`; приложение его не импортирует, production-сборка его не содержит. Playwright загружает настоящие модули приложения и ONNX в Chromium, сравнивает все 11 выходов на каждом входе.

Допуски абсолютной ошибки: признаки `1e-10`, float32 после scaler `2e-6`, выход модели `1e-5`. Все значения должны быть конечными, argmax должен совпадать на всех примерах. Измеренные результаты см. `STATUS.md`.

Новые выражения требуют настоящих размеченных видео конкретного, согласованного жестового языка: проверенные носителем/специалистом Hello, How are you?, I’m fine, плюс нейтральные и посторонние движения. Нужны несколько исполнителей и независимые сессии, разные условия камеры, согласие на использование записей, источник и версия обработки. Делить по исполнителям/сессиям/исходным видео **до** нарезки окон; scaler обучать только на train. Условные команды интерфейса реализованы геометрическими правилами в отдельной области; им не нужны новые классы ONNX. Их безопасность и удобство требуют проверки на физических камерах.
