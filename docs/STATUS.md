## Текущий этап: условные команды и исправление черновика (30.09.2026)

Браузерный ONNX, WebRTC и английские субтитры уже реализованы; устаревшее описание этапа в AGENTS.md обновлено. Существующие веса, словарь, признаки, лицензия и история Git сохранены.

### Реализовано

- `camera.ts` отдельно предоставляет все 21 точки каждой кисти. Возвращаемые кончики пальцев, порядок рук и точки тела для ONNX не изменены.
- Собственные геометрические правила в `commands.ts`: ладонь — включить общение/отправить черновик, кулак — отменить черновик, V — запросить завершение. Это условные команды интерфейса, а не перевод жестового языка.
- Видимая рамка вверху справа на зеркальном собственном видео, вход после 0,7 с, отдельное удержание команды 1 с, однократное действие и повторное взведение после 0,45 с нейтрального положения/выхода из рамки. Переходы, некорректные точки и две руки в рамке не запускают команды.
- Стабильный черновик сохраняется до отправки/отмены, включая смену позы и потерю отслеживания. Во время входа/управления классификация слов приостановлена, буфер очищен; после выхода нужны новые кадры. Отправка проверяет доступность DataChannel. Отменённое/отправленное слово подавляется до нейтрального периода без рук.
- V открывает подтверждение на 12 с. Только после нейтрального положения и нового удержания ладонь завершает, кулак отменяет. При остановке камеры, скрытии вкладки или отсутствии новых кадров запрос сбрасывается.
- Выбираемое обучение трём командам с подсказками по конкретным пальцам, видимости, области и углу V. Обучение не выполняет действия; неизвестному намерению не назначается произвольная команда для исправления.
- Точки запускаются автоматически после разрешения камеры в звонке. Общение включается ладонью без кнопки. Черновик, подсказка и удержание видны прямо на видео; дополнительные инструкции и обучение находятся ниже.

### Автоматические проверки

- Сборка TypeScript/Vite прошла; модульные тесты фронтенда **22/22**, сервер комнат **3/3**.
- Полный браузерный набор **9/9**: существующие звонок, RTP audio/video, ACK, дедупликация, потеря сигналинга, освобождение ресурсов, отказы разрешений и реальная загрузка модели/MediaPipe сохранены. Новый тест проводит два клиента через включение ладонью, сохранение черновика, паузу ONNX, накопление свежих кадров, однократную отправку, отмену и двухэтапный выход без кнопок жестов.
- Геометрические unit-тесты и новый сценарий используют явно синтетические landmarks; слово `day` в новом сценарии подставляется только тестом. Production не содержит входов для этих подстановок. WebRTC/канал сообщений в сценарии настоящие. Это проверка реализации, а не точности распознавания людей.
- Отдельная проверка настоящего ONNX WASM против Keras: **32/32** совпадений класса, ошибка выхода **4.76837158203125e-7** при допуске **1e-5**; признаки **3.3306690738754696e-16**, нормализация float32 **0**.
- Проверка готовой сборки через Node: **6/6**. Модульный браузерный сценарий с подстановкой landmarks запускается в dev-наборе; production-проверки используют настоящую загрузку модели и точек.

### Что Нурдаулету проверить вручную

Физическая камера в этой среде не проверялась. Нужны обе руки, разные люди/освещение/расстояния, точность подсказок пальцев и V, совпадение рамки при портретной камере, ложные команды при обычных движениях, удобство удержаний и повторного взведения. Следующий конкретный шаг — пройти раздел «Ручная проверка для Нурдаулета» в README на двух устройствах по HTTPS. Отдельно нужны живые микрофоны/STT, эхо, разные сети и настоящий TURN.

После подключения участник может управлять словесными сообщениями и завершением без мыши. Создание/приглашение, выбор обучения, включение микрофона и субтитров, повторное разрешение/включение выключенной камеры остаются обычными элементами интерфейса. Полностью бесконтактное управление всеми функциями не заявляется. Hello / How are you? / I’m fine по-прежнему не обучены.

## Сохранённый этап: звонок на двоих (30.09.2026)

Реализованы главная/приглашение, комнаты на двух участников, Node + ws сервер сигналинга, SDP/ICE, WebRTC видео и аудио, DataChannel с ACK и дедупликацией, имена отправителей, промежуточные/окончательные субтитры, история после завершения. Существующая модель подключена к локальной камере звонка через те же `core.ts`, `camera.ts`, `model.ts`. Локальная диагностика сохранена по `?mode=local`.

Добавлены управление камерой/микрофоном, ручные подтверждение/отмена черновика, текстовое уточнение, отдельная панель словаря/диагностики. STT использует английский Web Speech API и локальный микрофон по умолчанию; на время диктовки удалённый звук выключается. Отказ камеры/микрофона, отсутствие API, ошибки STT, ожидание, занятая/закрытая комната, потеря сигналинга и выход имеют состояния. При выходе ресурсы освобождаются у обоих. STUN/TURN/TLS настраиваются через `server/.env`; TURN shared secret остаётся на сервере.

### Проверки текущего этапа

- Production через Node static server: **6/6** браузерных проверок на порту 3002.

- В реальном Chromium 140 обнаружены `SpeechRecognition` и `webkitSpeechRecognition`. Доступность внешнего сервиса и качество живой речи не доказаны. Speech events в интеграционном тесте — явно синтетическая fixture только в тестах; видео/микрофон также стандартные fake devices Chromium.

### Не проверено на реальных устройствах

Физические камеры/микрофоны, настоящие жесты, живая английская речь через сервис, акустическое эхо, мобильные браузеры, HTTPS deployment, разные сети и настоящий TURN relay. Локальное соединение двух клиентов не подтверждает работу через NAT разных операторов. Веса/классы неизменны; Hello / How are you / I’m fine не поддерживаются.
