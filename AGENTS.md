Продукт
SignBridge — рабочее название браузерного видеозвонка на двоих:
- глухой участник показывает поддерживаемый жест или выражение;
- приложение распознаёт его и передаёт текст собеседнику;
- слышащий участник отвечает голосом;
- распознанная речь появляется субтитрами у второго участника.
Первый законченный сценарий: создать комнату → подключить собеседника по ссылке → обменяться короткими сообщениями → исправить обнаруженную неточность → завершить звонок и увидеть историю разговора.
Это прототип с ограниченным словарём. Не позиционируй его как универсальный переводчик жестового языка.
Целевые выражения для будущего обучения:
- Hello!
- How are you?
- I'm fine.
Это желаемые значения, а не уже поддерживаемые классы. Сначала выбери и документируй конкретный жестовый язык и проверь соответствующие движения. Не придумывай жесты, выдавая их за настоящие. Если используются условные команды, явно называй их условными.
Требования хакатона ADMIT MOTION
Источник требований — кейс и сообщения организаторов, переданные пользователем.
- Распознавание движений в реальном времени непосредственно в браузере.
- Минимум три разных движения, вызывающих разные действия.
- Видимая обратная связь: точки, подсветка, статус, результат.
- Законченный пользовательский сценарий.
- Пользователю не нужно устанавливать приложение.
- Основной сценарий управляется жестами без клавиатуры и мыши. Браузерные разрешения камеры и микрофона обрабатываются штатным способом.
- Обязательный режим «ошибка»: конкретные рекомендации по исправлению.
- Публичный репозиторий, README с запуском, описание движений и режима ошибок; рабочий деплой крайне желателен.
Для явного выполнения условия о разных действиях предусмотрены отдельные жестовые команды подтверждения сообщения, отмены черновика и завершения разговора. Это план, а не готовая функциональность. Их назначения не должны конфликтовать с распознаванием речи жестами; опасные для разговора команды требуют удержания или подтверждения.

Исходный репозиторий и проверенная база
Происхождение заимствованных компонентов учитывается по исходной ревизии и LICENSE.
Проверенная исходная ревизия: eb069bd0740ee916eb22e11069f8602800d6af2c.
В upstream указана MIT License; сохраняй LICENSE и уведомления об авторстве.
Исходный стек: Python, Flask, MediaPipe, TensorFlow/Keras, OpenCV; Celery, Redis и SQLite используются в существующей инфраструктуре.
Основные файлы:
- real_time_inference.py — локальное распознавание;
- app/utils/real_time_recognition.py — распознавание для Flask;
- app/utils/feature_extraction.py — обработка признаков;
- app/routes.py — маршруты;
- train.ipynb — обучение;
- app/model/sign_language_recognition.keras;
- app/model/scaler.pkl;
- app/model/label_encoder.pkl;
- app/model/feature_order.json.
На проверенной ревизии:
- модель получает последовательность формы (batch, 5, 18);
- архитектура включает LSTM, BatchNormalization и Dense;
- имеется 11 классов: afternoon, age, boy, country, day, monday, name, night, people, person, time;
- признаки основаны на статистиках координат кончиков пальцев и суставов верхней части тела;
- Flask открывает камеру компьютера с Python через OpenCV, а не камеру удалённого посетителя;
- видеозвонок, speech-to-text, браузерный inference и конкретные подсказки ошибок отсутствуют;
- точность на камере пользователя не проверена.
Повторно сверяй эти сведения с текущим кодом при изменениях. Новые подписи классов не обучают модель новым движениям. Английские названия слов не доказывают принадлежность движений к ASL.

Архитектурные ориентиры
- Если подходящего фронтенда ещё нет, используй React + TypeScript + Vite в web/. Не создавай второй фронтенд поверх уже реализованного.
- Камера — getUserMedia; точки рук/тела — браузерный MediaPipe; модель — совместимый TensorFlow.js либо ONNX Runtime Web. Выбор проверь, не обещай автоматическую конвертацию.
- Python допустим для подготовки данных, обучения и экспорта. Финальный inference жестов выполняется на клиенте.
- Не переноси Flask, Redis и Celery в пользовательский путь только потому, что они есть в upstream.
- Для звонка планируется WebRTC и минимальный сигналинг. Учитывай необходимость TURN для части сетей; не заявляй надёжность звонков только по тесту двух вкладок.
- Начальный язык распознавания речи — английский. Выбери реализацию по реальной поддержке целевых браузеров. Не обещай локальную обработку speech-to-text, если выбранный механизм отправляет звук сервису.
- Храни ключи сервисов на сервере; документируй настройки в .env.example без секретов.
- Не сохраняй видео, аудио и историю разговора постоянно по умолчанию. Запись для датасета должна запускаться явным действием пользователя.
Корректность распознавания
- Сохраняй совместимость нормализации, порядка признаков, масштаба, ориентации, порядка рук, временных окон и пропусков точек.
- Проверь соответствие обучения и inference; не исправляй признаки молча, продолжая использовать несовместимые веса.
- Изменение способа определения левой/правой руки может потребовать переобучения.
- Пропускай обработку, если предыдущий inference ещё не завершён; освобождай тензоры и медиатреки.
- Разделяй кандидат, подтверждённое сообщение и неопределённый результат.
- Добавь стабилизацию, пороги принятия, подавление повторов и сброс устаревшего буфера при потере отслеживания.
- Отсутствие рук, неподдерживаемое движение и низкая уверенность не должны автоматически превращаться в отправленную фразу.
- Softmax/confidence не является доказанной вероятностью правильного перевода. Пороги проверяются экспериментально.
- Не используй случайные результаты, таймеры или заранее заготовленные ответы под видом реального распознавания. Тестовые фикстуры маркируй и отделяй от пользовательского режима.
Режим «ошибка» и интерфейс
Подсказка должна исходить из измеримого состояния и предлагать конкретное действие, например: «Перемести руку ближе к центру — она у края кадра».
Не требуй две руки для любого жеста. Не утверждай, что пользователь должен изменить конкретный палец, если его предполагаемый жест неизвестен. Подробное сравнение с эталоном уместно в обучении заранее выбранному жесту.
Отделяй проблему видимости камеры от неопределённости модели и от ошибки выполнения. Один процент уверенности или надпись «не распознано» не выполняют твист.
Показывай крупные субтитры, доступный словарь и состояние системы. Предусмотри отказ в разрешении, отсутствие камеры/микрофона, загрузку модели, потерю связи и завершение звонка. Цвет не должен быть единственным сигналом. Не перегружай продукт техническими подробностями.

- В исходном notebook окна делились случайно; учитывай риск завышенной оценки.
- Сохраняй происхождение данных, определения классов, параметры обработки и версию модели.
- Проверяй сборку фронтенда, соответствие Python/browser на одинаковых входах, подавление повторов и потерю отслеживания.
- Синтетический тест подтверждает реализацию, но не качество перевода реальных жестов.
- Если камера или второй участник недоступны, перечисли непроверенное и дай короткие ручные проверки.
- Не выдумывай результаты тестов, точность, скорость и работающий деплой.
