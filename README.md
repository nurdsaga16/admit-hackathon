# SignBridge

**Видеозвонок, в котором сообщения можно увидеть.**

SignBridge — браузерный прототип для общения глухого и слышащего участников. Один показывает заданное движение и подтверждает назначенную ему фразу. Другой отвечает голосом, а английская речь появляется у собеседника субтитрами.

Проект разрабатывается для хакатона **ADMIT MOTION**. Пользователю достаточно открыть ссылку в браузере: устанавливать приложение не нужно.

> 11 заданных движений для общения готовыми фразами. Это условные жесты, а не перевод жестового языка. Фразы назначены существующим классам; модель не переобучалась настоящим жестам Hello или How are you?.

## Назначенные разговорные фразы

Единый источник соответствий — `web/src/phraseMapping.ts`, функция `getPhrase(classId)`. Для неизвестной метки она возвращает исходную строку. Изменять назначения нужно только в этом файле.

| Исходный класс | Назначенная фраза |
|---|---|
| person | Hello |
| afternoon | How are you? |
| age | I'm fine |
| boy | What's your name? |
| country | Nice to meet you |
| day | Thank you |
| monday | You're welcome |
| name | Please repeat |
| night | Goodbye |
| people | I need help |
| time | One moment, please |

Это пользовательские назначения существующим движениям, не их настоящий перевод. Веса, словарь ONNX, порядок классов, признаки, нормализация и пороги сохранены. Стабилизация, отмена и подавление повторов используют исходные ID. Фраза появляется в черновике и после подтверждения передаётся собеседнику; история обоих участников и субтитры получателя показывают один и тот же отправленный текст. Обычный текст и распознанная речь не преобразуются.

В диагностике фраза показана вместе с классом, например `How are you? — класс afternoon`; проценты относятся к оценке класса. На странице примеров файловые ID и метки остаются исходными. Назначение `night → Goodbye` отправляет сообщение и само по себе не завершает звонок: управление ладонь/кулак/V осталось отдельным.

## Как проходит разговор

1. Выбери «Начать звонок» или «Присоединиться». Имя необязательно. «Жестами / Голосом» выбирает удобный интерфейс, способ можно поменять в звонке.
2. Разреши камеру. Нажми «Пригласить», скопируй ссылку и отправь собеседнику. При открытии приглашения комната уже выбрана.
3. В режиме «Жестами» включи распознавание кнопкой или удержанием ладони в рамке. «Твоя фраза» показывает следующий шаг и конкретную подсказку. «Как показать фразу?» открывает записи датасета внутри звонка.
4. Проверь крупный черновик и нажми «Отправить» либо удержи ладонь в рамке. «Повторить» или кулак отменяет черновик; перед новым повтором убери руки из кадра на секунду. Технические оценки, кадры и устойчивость находятся в подробностях.
5. В режиме «Голосом» нажми «Начать говорить с субтитрами». Приложение запросит микрофон и запустит английское распознавание. Пока оно слушает, звук собеседника временно выключен для защиты от эха. Сервис браузера может обрабатывать звук удалённо.
6. «История» открывает переписку и поле текста; «Помощь» — примеры, обучение и переход к диагностике. Панели не пересоздают медиапотоки. На телефоне они открываются снизу; закрываются кнопкой или Escape.
7. Заверши звонок кнопкой или двухэтапной командой V → нейтральное положение → ладонь. Кулак отменяет выход. У обоих останется история разговора.

Комната рассчитана на двух человек. Выход любого участника завершает её; для следующего звонка нужно создать новую ссылку.

## Что реализовано

- Создание комнаты, приглашение ссылкой и отказ третьему участнику.
- Двусторонний видеозвонок и передача звука через WebRTC.
- Распознавание жестов непосредственно в браузере с точками рук и тела поверх видео.
- Черновик, подтверждение слова, три наиболее вероятных результата и настраиваемые пороги.
- Английские промежуточные и окончательные субтитры через Web Speech API.
- Сообщения с именами отправителей, подтверждением доставки и защитой от дублей.
- Ручной ввод текста для уточнений.
- Управление камерой и микрофоном, состояния ошибок и история после завершения.
- Отдельная панель словаря и диагностики.

Реализованы три **условные команды интерфейса**, отдельные от распознавания слов. Это не перевод жестового языка и не новые классы ONNX. Создание комнаты, копирование ссылки, выбор обучения, управление микрофоном и включение субтитров пока используют обычные элементы интерфейса; браузерные разрешения выдаются штатным способом. После подключения и разрешения камеры участник может включить общение, подтвердить/отменить черновик и завершить звонок без мыши.

## Условные команды и исправление ошибок

Точки загружаются автоматически после открытия камеры в звонке. Кнопка «Включить жесты» необязательна: первое удержание ладони включает общение.

| Команда в рамке | Действие |
|---|---|
| Раскрытая ладонь, все пять пальцев разогнуты | Включить общение; затем подтвердить сохранённый черновик при наличии соединения |
| Кулак, все пальцы согнуты | Отменить черновик, чтобы повторить слово |
| V: указательный и средний разогнуты и разведены, остальные согнуты | Запросить завершение звонка |

1. Переведи **центр ладони** в подсвеченную рамку вверху справа на зеркальном собственном видео. Вход требует **0,7 с**, затем сама команда — **1 с** непрерывного удержания. Полоса показывает текущий этап, текст — оставшееся время.
2. Уже при входе обработка слов приостанавливается и её временной буфер очищается. Первый устойчивый черновик сохраняется до отправки или отмены; смена позы и потеря точек его не заменяют.
3. Каждая команда срабатывает один раз. Для повторного взведения покажи переходное положение (например, один указательный палец) или убери руку из рамки минимум на **0,45 с**. Просто заменить ладонь кулаком недостаточно.
4. Выйди из рамки для распознавания слов: сбор 35 пригодных кадров начинается заново. Чтобы снова распознать отменённое или отправленное слово, убери руки из кадра на секунду.
5. После V появится подтверждение: нейтральное положение, затем **ладонь — выйти**, **кулак — продолжить**. Запрос автоматически отменяется через **12 с**, при остановке камеры или потере поступления кадров. Одно удержание V звонок не разрывает.

В **«Помощь → Управление ладонью, кулаком и V»** выбери ладонь, кулак или V. Приложение измеряет сгибы суставов и расположение точек, называет пальцы, которые нужно согнуть/разогнуть, подсказывает направление перемещения кисти и оставшееся время. Для V проверяется угол разведения 15–65°. Обучение не отправляет сообщения и не завершает звонок; кнопка «Закончить обучение» выходит из него. Без выбранного намерения приложение сообщает только о видимости, переходном положении и удержании.

Геометрия использует полные 21 точки кисти, масштаб и пропорции кадра; вход модели слов по-прежнему содержит только исходные кончики пальцев и точки тела. В рамке достаточно одной руки; две руки внутри рамки блокируют команду. Пороги геометрии и времени находятся в `web/src/commands.ts`. Они требуют проверки на реальных руках: автоматические тесты не доказывают точность на камере.

### Ручная проверка для Нурдаулета

На двух устройствах по общей HTTPS-ссылке:

1. Разреши камеру, не нажимай «Включить жесты»: включи общение ладонью в рамке. Проверь совпадение рамки с рукой на зеркальном видео.
2. Получи черновик поддерживаемого слова вне рамки. Переведи руку в рамку, меняй позы: черновик должен сохраниться. Отправь ладонью и удерживай её ещё несколько секунд — сообщение должно остаться единственным у обоих.
3. Отмени следующий черновик кулаком; убери руки на секунду и повтори слово. Проверь, что во время команд слова не меняются.
4. В обучении каждой команде намеренно согни нужный палец, не разведи V, подойди к краю: сравни подсказку с реальным положением. Проверь обе руки, освещение, расстояние и портретную камеру.
5. Покажи V кратко — ничего не должно завершиться. Удержи V, затем без нейтрального положения ладонь — выход не должен произойти. После нейтрального положения кулак отменяет запрос; в следующей попытке ладонь завершает разговор и открывает историю у обоих.
6. Проверь исчезновение руки, закрытие вкладки, отключение камеры и потерю связи. Отдельно проверь настоящую речь, эхо и TURN между разными сетями.

## Быстрый запуск

### Требования

- **Node.js 22.15 или новее** и npm.
- Браузер с камерой; микрофон нужен для голосового ответа.
- Интернет для первоначальной загрузки зависимостей и моделей MediaPipe.
- Python нужен только для повторного экспорта или обучения модели.

Команды ниже проверялись в Windows PowerShell. Начинай из корня репозитория.

### Установка

```powershell
npm --prefix server ci
npm --prefix web ci
npm --prefix web run assets
```

Команда `assets` подготавливает файлы WebAssembly и скачивает модели точек рук и тела. Готовая модель распознавания слов уже находится в `web/public/model/`.

### Запуск готовой сборки

```powershell
npm --prefix web run build
cd server
npm start
```

Открой **http://127.0.0.1:3001**. Один сервер обслуживает интерфейс и соединение комнат.

**Оставь терминал работающим.** Закрытие процесса выключит сервер.

### Режим разработки

После установки зависимостей открой два терминала в корне проекта.

**Терминал 1 — сервер комнат:**

```powershell
cd server
npm start
```

**Терминал 2 — интерфейс:**

```powershell
cd web
npm run dev
```

Открой **http://127.0.0.1:5173**. Vite передаёт запросы комнат и сигналинга локальному серверу на порту 3001.

Проверка доступности сервера: **http://127.0.0.1:3001/api/health**. Ожидаемый ответ — `{"ok":true}`.

## Подключение с двух устройств

Для разных устройств нужен **один доступный обоим HTTPS-адрес**, которому доверяют их браузеры.

- `127.0.0.1` и `localhost` указывают на текущее устройство.
- Обычный HTTP по адресу компьютера в локальной сети не обеспечивает доступ к камере.
- Можно включить HTTPS непосредственно в Node-сервере или поставить перед ним HTTPS-прокси с поддержкой WebSocket.
- Для части сетей потребуется TURN — сервер, через который WebRTC передаёт данные, когда прямое соединение недоступно.

После настройки открой общий HTTPS-адрес на первом устройстве, создай комнату и передай полученную ссылку второму участнику. Проверь видео, звук, отправку сообщения и завершение звонка.

**Подробные примеры сертификатов, окружения и проверки разных сетей:** [настройка звонка](docs/CALL.md).

### Переменные окружения

Для локального запуска значения по умолчанию подходят без файла настроек. Чтобы изменить их, из корня проекта выполни:

```powershell
Copy-Item server/.env.example server/.env
```

Сервер читает `server/.env` при запуске через `npm start`. После изменения настроек перезапусти его.

| Переменная | Назначение |
|---|---|
| `HOST` | Адрес сервера: `127.0.0.1` локально, `0.0.0.0` для доступа через сетевые интерфейсы |
| `PORT` | Порт сервера; по умолчанию `3001` |
| `ALLOWED_ORIGINS` | Разрешённые адреса сайтов через запятую |
| `TLS_CERT_FILE`, `TLS_KEY_FILE` | Пути к сертификату и приватному ключу для HTTPS |
| `STUN_URLS` | Адреса STUN через запятую; по умолчанию используется Google STUN |
| `TURN_URLS` | Адреса отдельно развёрнутого TURN-сервера |
| `TURN_SHARED_SECRET` | Серверный секрет для создания временных учётных данных TURN |
| `TURN_TTL_SECONDS` | Срок действия учётных данных TURN; по умолчанию 3600 секунд |
| `ICE_TRANSPORT_POLICY` | `all` — доступные способы соединения; `relay` — только через TURN |
| `MAX_ROOMS` | Максимальное количество комнат; по умолчанию 1000 |

Фронтенду отдельный файл окружения не требуется. TURN-секрет и приватный ключ должны оставаться на сервере. Vite в режиме разработки ожидает сервер на порту 3001.

## Распознавание жестов

Камера открывается через браузерный `getUserMedia`. MediaPipe определяет точки рук и тела, после чего модель выполняется через **ONNX Runtime Web / WebAssembly** на устройстве участника.

Словарь текущей модели:

```text
afternoon, age, boy, country, day, monday,
name, night, people, person, time
```

Это названия классов, а не инструкции по выполнению движений. Принадлежность исходных жестов конкретному жестовому языку и эталонные движения ещё требуют проверки.

Модель получает последовательность из пяти окон по 18 признаков. Первое предсказание требует 35 пригодных кадров. Для черновика нужны несколько устойчивых результатов; один удерживаемый подтверждённый жест не должен отправляться повторно. Чтобы повторить слово, убери руки из кадра примерно на секунду и покажи движение снова.

Оценка модели не является доказанной вероятностью правильного перевода. Незнакомый жест тоже может получить высокую оценку, поэтому результат нужно проверить перед подтверждением.

### Подсказки при ошибках

| Измеримое состояние | Подсказка или действие приложения |
|---|---|
| Руки не обнаружены | Показать хотя бы одну руку перед камерой |
| Рука у края кадра | Переместить её ближе к центру |
| Не видны нужные точки тела | Отойти и разместить плечи, локти и запястья в кадре |
| Потеря отслеживания или задержка кадров | Сбросить устаревшую последовательность |
| Низкая оценка или нестабильный класс | Показать неопределённость и не предлагать отправку |

Две руки не требуются для каждого движения. Приложение не указывает, какой палец нужно исправить, если предполагаемый жест неизвестен.

### Примеры движений из исходного датасета

Открой **http://127.0.0.1:3001/?mode=examples** (в dev-режиме порт 5173) или ссылку «Примеры движений из датасета» на главной. Доступны по три записи для каждого из 11 слов, выбор блока наблюдений, воспроизведение, пауза, кадры и отражение.

Это реальные записанные координаты из Kaggle, **визуализация датасета, а не полноценная инструкция по жестовому языку**. Видео в архиве нет, в базе только локальные пути без HTTP-ссылок. Язык, зеркальность камеры, FPS и пропорции кадра не подтверждены. Повторные наборы landmarks разделены по порядку записей, но их принадлежность оригиналу или зеркальному проходу не доказана. Отсутствующие точки не дорисовываются; скорость просмотра условная.

База и экспортированные координаты исключены из Git. После клонирования их нужно подготовить отдельно:

```powershell
python scripts/export_dataset_examples.py data-local/sign-language-recognition.sqlite
npm --prefix web run build
```

[Скачивание, структура базы, ID записей и ограничения восстановления](docs/DATASET.md). В этой рабочей папке данные уже скачаны и экспортированы. Проверка SQLite выполнена только для чтения; веса модели не менялись.

### Локальная диагностика

Чтобы проверить модель без звонка, нажми **«Проверить распознавание»** на главной или открой:

- готовая сборка: **http://127.0.0.1:3001/?mode=local**;
- режим разработки: **http://127.0.0.1:5173/?mode=local**.

Здесь доступны камера, точки, словарь, оценки, настройка порогов и локальная история.

### Повторный экспорт модели

Из корня проекта, в PowerShell:

```powershell
python -m venv .venv-export
.\.venv-export\Scripts\python -m pip install -r scripts/requirements-export.txt
.\.venv-export\Scripts\python -X utf8 scripts/export_model.py
```

Экспортёр переносит существующие веса, параметры нормализации и словарь; новых жестов он не обучает. Он также создаёт синтетические эталоны для сравнения Python и браузера.

Архитектура, допуски и обнаруженные расхождения подготовки данных описаны в [документации модели](docs/MODEL_PORT.md).

## Распознавание речи

Начальный язык — **английский, `en-US`**. Используется браузерный Web Speech API. Приложение проверяет наличие API и сообщает об отказе разрешения, недоступности микрофона или ошибке сервиса.

- Распознаётся локальный микрофон по умолчанию. Поток собеседника не передаётся распознавателю.
- Во время диктовки звук собеседника временно выключается, чтобы снизить риск распознавания эха. Для разговора используй наушники.
- Промежуточный текст обновляется на экране; в историю попадает окончательная версия.
- Одинаковое событие не должно создавать повторное сообщение.
- Отключение микрофона и завершение звонка останавливают распознавание.

Наличие API не гарантирует доступность сервиса. Браузер может отправлять звук внешнему сервису распознавания; работа без интернета не обещается. Проверка живой речи на реальных устройствах ещё предстоит.

## Данные и приватность

- Приложение не записывает видео и аудио постоянно по умолчанию.
- Сервер комнат обменивается служебными сигналами соединения и не сохраняет историю сообщений.
- Медиа и сообщения передаются через WebRTC; при необходимости используется TURN.
- История находится в памяти вкладки и исчезает при перезагрузке или выходе на главную.
- Ссылка даёт доступ к комнате: отправляй её только собеседнику.
- Обработка речи сервисом браузера отличается от локального выполнения жестовой модели.

## Проверки

Из корня проекта:

```powershell
npm --prefix server test
npm --prefix web test
cd web
npx playwright install chromium
npm run test:browser
npm run build
npx playwright test --config playwright.production.config.ts
```

Последние зафиксированные результаты:

| Проверка | Результат |
|---|---|
| Сборка TypeScript и Vite | Успешно |
| Модульные тесты фронтенда | 24 из 24 |
| Тесты сервера комнат | 3 из 3 |
| Браузерные проверки | 12 из 12 |
| Проверки готовой сборки через Node-сервер | 8 из 8 |
| Совпадение выбранного класса Python и браузера | 32 из 32 синтетических входов |
| Максимальная абсолютная ошибка выхода модели | `4,77 × 10⁻⁷` при допуске `10⁻⁵` |

Автоматические проверки используют настоящие WebRTC-соединения и модель, но тестовые камеры и микрофоны. События распознавания речи в проверке передачи субтитров подставляются только тестом. Новый тест управления использует синтетические точки кисти и результат слова, проверяя переходы и передачу сообщений; отдельный тест численного соответствия выполняет настоящую ONNX-модель.

**Эти результаты не подтверждают** точность распознавания жестов людей, качество живой речи, отсутствие акустического эха или надёжность связи между разными сетями. Физические устройства, мобильные браузеры и реальный TURN требуют отдельной проверки.

Актуальные результаты и ограничения: [состояние проекта](docs/STATUS.md).

## Если что-то не работает

| Проблема | Что проверить |
|---|---|
| Страница не открывается | Процесс сервера работает; для разработки также запущен Vite. Используй адрес соответствующего режима |
| Комната не создаётся | Сервер отвечает по `/api/health`; Vite передаёт запросы на порт 3001 |
| Камера или микрофон недоступны | Разрешения сайта, наличие устройства, другие приложения, HTTPS или localhost |
| Модель не загружается | Выполни `npm --prefix web run assets`; проверь файлы в `web/public/model/`. Для готовой версии повтори сборку |
| Второе устройство не открывает ссылку | В ссылке указан общий HTTPS-адрес, а не localhost; сертификат доверенный, порт доступен |
| Видео не соединяется между сетями | Проверь настройки STUN/TURN и доступность TURN-сервера |
| Субтитры недоступны | Браузер предоставляет Web Speech API, микрофон разрешён, сервис распознавания доступен |
| Комната закрыта или занята | Создай новую комнату либо проверь, нет ли уже двух участников |

## Устройство проекта

| Путь | Назначение |
|---|---|
| `web/src/` | Интерфейс, WebRTC, распознавание жестов и речи |
| `web/public/model/` | ONNX-модель и параметры обработки |
| `web/tests/` | Модульные и браузерные проверки |
| `server/` | Сервер комнат, сигналинг и выдача собранного интерфейса |
| `scripts/` | Экспорт модели и зависимости подготовки |
| `app/model/` | Исходные веса и параметры нормализации |
| `app/`, `train.ipynb` | Сохранённые Python-компоненты и материалы обучения |
| `docs/` | Технические пояснения, проверки и текущее состояние |

Основной стек: **React, TypeScript, Vite, MediaPipe, ONNX Runtime Web, WebRTC, Node.js и WebSocket**. Python используется при подготовке модели. Flask, Redis, Celery и OpenCV не нужны для запуска браузерного звонка.

## Дальнейшая работа

1. Проверить звонок на физических устройствах, живую английскую речь и связь между разными сетями через TURN.
2. Установить конкретный жестовый язык и проверить эталонные движения со специалистом.
3. Собрать размеченные видеопоследовательности для **Hello, How are you?, I’m fine**, а также нейтральных и посторонних движений.
4. Разделить данные по исполнителям, сессиям или исходным видео до нарезки окон; обучить и независимо проверить модель.
5. Проверить геометрию команд на реальных исполнителях и расширить доступность управления вне сценария сообщений.
6. Подготовить публичное размещение и проверить полный сценарий хакатона.
